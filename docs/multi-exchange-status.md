## 1. Контекст (зачем всё это)

Binance с 01.07.2026 приостановил обслуживание резидентов ЕС (не получил лицензию MiCA
к дедлайну). Приложению нужна торговля через MiCA-лицензированные площадки. Из ~3000+
крипто-компаний ЕС полную MiCA-авторизацию получили ~210 (~7%), включая Coinbase,
Kraken, OKX, Crypto.com.

в `apps/shared_data/lib/shared_data/schemas/api_credential.ex`.

## 3. ⚠️ Про API-ключи для других бирж

**Готовых ключей для OKX / Kraken / Coinbase НЕТ и не было.** В `.env` и окружении
присутствуют только `BINANCE_API_KEY` / `BINANCE_SECRET_KEY` (тестовые). Реализован
*код адаптеров*, но учётные данные к чужим биржам появляются только когда их создаёт
сам пользователь в личном кабинете соответствующей биржи. Подставить/сгенерировать их
нельзя.

Чтобы реально протестировать вторую биржу — проще всего **OKX**: у неё живой demo-режим
(Trade → Demo Trading → Personal Center → Demo Trading API), ключи не истекают. Добавить
их через форму `/admin/accounts`, задать `OKX_DEMO=true`. Пошаговый сценарий —
`docs/superpowers/notes/okx-e2e-checklist.md`.

## 4. Аутентификация и особенности по биржам (кратко)

- **Binance:** HMAC-SHA256, заголовок `X-MBX-APIKEY`. Символы `BTCUSDT`.
- **OKX:** key + secret + **passphrase** (3-й секрет), HMAC-SHA256, ISO8601-timestamp,
  заголовок `x-simulated-trading: 1` в demo. Символы `BTC-USDT`. Нюанс market-buy:
  `tgtCcy: "base_ccy"`, иначе `sz` = в валюте котировки.
- **Kraken:** HMAC-SHA512 над `path <> SHA256(nonce <> body)`, секрет base64-декодируется,
  строго возрастающий nonce. Символы «грязные»: `XBT`↔`BTC`, `XDG`↔`DOGE`, три формата
  имён пар (altname/wsname/pair). WS v2, приватный канал executions через отдельный токен.
- **Coinbase:** CDP-ключи, **ES256 JWT** на каждый запрос (через уже имевшийся в проекте
  `jose`). EC-приватный ключ (PEM) хранится Cloak-зашифрованным в поле `secret_key`.
  Символы `BTC-USD`. Нюанс: статус `CANCELLED`→`CANCELED`; часть ликвидности в USDC/EUR,
  а не USDT (влияет на совместимость символов вида `BTCUSDT`).

Все адаптеры **нормализуют ответы в Binance-совместимый формат** (ключи REST-ордеров,
тикеров, executionReport; статусы → NEW/PARTIALLY_FILLED/FILLED/CANCELED). Это сознательное
транзитное решение: стратегии Naive/Grid/DCA/ConditionalChain работают без переписывания.
Канонический рефакторинг payload (уход от сырых Binance-ключей) — отложен в Future work.

## 5. Как это выглядит в интерфейсе (`/admin/accounts`)

**Добавление аккаунта** (кнопка Add Trading Account):
- Выпадающий список **Exchange** — все 4 биржи выбираемы.
- Поле **Passphrase** появляется и обязательно только при выборе **OKX**.
- Серверная валидация (`validate_inclusion`) независимо отклоняет неподдерживаемую биржу,
  даже если обойти UI через devtools.
- Биржа **неизменяема после создания** (в форме редактирования не кастуется).

**Список аккаунтов** — вертикальные карточки, у каждой:
- название + бейдж статуса (**Active**/**Inactive**) + **бейдж биржи** (Binance/OKX/
  Kraken/Coinbase) + бейдж **Testnet** (если тестовый);
- маскированный API-ключ, «Exchange Account ID», время обновления;
- кнопки: **Test Connection**, **Deactivate/Activate**, **Edit**, **Delete**.

**Сценарии, которые вы спрашивали:**
- *Временно скрыть / отказаться от старого аккаунта* → **Deactivate**: остаётся в списке
  с серым бейджем «Inactive», стратегии на нём не запускаются, ключи сохраняются; обратно
  — **Activate**.
- *Совсем убрать* → **Delete** (с подтверждением): удаляет аккаунт вместе с зашифрованными
  ключами безвозвратно.
- *Аккаунт от другого провайдера* → та же карточка, но с другим бейджем биржи; список
  показывает все аккаунты вперемешку.

**Известное ограничение UI (ещё не сделано):** список показывает ВСЕ аккаунты вместе, без
фильтра «только активные» и без сворачивания неактивных. При большом числе аккаунтов
стоит добавить фильтр/сортировку по активности.

## 6. Что НЕ входит (Future work)

- **Экраны `dashboard_web`** (portfolio/history/trading/orders LiveViews, ~20+ мест) всё
  ещё вызывают `BinanceClient` напрямую — не-Binance аккаунты получили поддержку на уровне
  движка (стратегии, ордера), но эти экраны показывают только Binance-данные.
- **Unified-вид портфеля** (агрегированные балансы/позиции по всем биржам в одном месте) —
  из исходного дизайна, не реализован.
- **Фильтр/сортировка списка аккаунтов** по активности.
- **Канонические payload-структуры** вместо сырых Binance-ключей в стратегиях.
- `TradingEngine.OrderManager` — мёртвый код (0 вызовов), решение отложено.

## 7. Тестовое покрытие и качество

- Полный прогон: **263 теста, 0 падений** (проверено лично на смёрженном master).
- Компиляция `--warnings-as-errors` чистая; `mix.lock` не менялся (jose уже был в дереве).
- Известная флаки-проблема тестов (гонка `restore_active_strategies` с Ecto-sandbox)
  устранена env-guard'ом (`restore_on_boot`, выключен в test).
- Починен краш-баг «Start Chain» в `chains_live.ex` (запускал трейдера без обязательных
  opts) — теперь через `StrategyManager`. Плюс фиксы зомби-трейдеров, утечки подписок,
  позиционного трекинга.

## 8. Как реализовывалось (процесс)

Все крупные этапы шли через агентные workflow (Sonnet — реализация и по-задачные ревью,
Opus — ревью спецификаций и финальные холистические проверки + фиксы). Финальный Opus
дважды ловил дефекты, пропущенные по-задачными проверками (напр., отсутствие
переподписки OKX-WS после реконнекта). Инцидент с месячным лимитом расходов был пережит
через resume workflow из кэша без потери прогресса.
